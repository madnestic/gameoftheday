## Что это

Сайт-хаб с мини-играми, играющимися прямо в браузере. Принципиально без скачиваний, без аккаунтов, без рекламы, без бэкенда. Однофайловое статическое приложение (`index.html`, ~100 KB) — HTML, CSS, JS, звуки через Web Audio API, всё в одном файле. Внешних зависимостей нет, только Google Fonts (Abyssinica SIL, Anton, Major Mono Display, JetBrains Mono).

Сейчас в проекте **две готовые игры**:
1. **Pongonoid** — гибрид Pong и Arkanoid против ИИ
2. **Space Slicer** — пинбол… нет, инвейдеры, в которых снаряд разрезает врага пополам, и половинки физически падают, рассыпаясь на пиксели

Главная — карточный хаб с узкими горизонтальными карточками (`№01 pongonoid`, `№02 space slicer`).

В `archive/pinball-808.html` лежит замороженный снимок незавершённой идеи **Pinball-808** (пинбол + 808-драм-машина с квантованием). Игра в `archive/` сохранена как есть, открывается и играется напрямую. Концепт-документ: `/Users/nikita/Downloads/PINBALL_808_CONCEPT.md`. К идее можно вернуться позже.

```
index.html
├── <style>                 — CSS для лендинга, игрового экрана, оверлеев, карточек хаба
├── <body>
│   ├── .hub                — лендинг (gameoftheday + .game-list с карточками)
│   ├── .game-screen        — общий экран игры (canvas + динамический header + overlay)
│   ├── .corner-meta        — плавающий бейдж (vol·01 / editions·02)
│   ├── .side-rules         — вертикальные подписи слева/справа (только ≥1100px)
│   └── <script>
│       ├── Hub navigation     — Games dict + setGameHeader() + диспетчер overlayBtn
│       ├── Pongonoid module   — IIFE, регистрируется как Games.pongonoid
│       └── SpaceSlicer module — IIFE, регистрируется как Games.slicer

archive/
└── pinball-808.html         — frozen-снимок (3000 строк), Pinball-808 + Pongonoid
```

Декорации (`corner-meta`, `side-rules`) — siblings `.hub` и `.game-screen`, скрываются автоматически через CSS `~`-селекторы, когда `.hub` получает класс `hidden` или `.game-screen` получает `active`.

### Мультиигровая инфраструктура

Каждая игра — изолированный IIFE-модуль, регистрирующийся через `Games[id] = { init, stop, onOverlayClick }`. Хаб-диспетчер:

- `data-game="<id>"` атрибут на карточке вызывает `Games[id].init()` при клике
- `BACK`-кнопка зовёт `currentGame.stop()`
- Общий `overlayBtn` (на оверлее) роутится в `currentGame.onOverlayClick()` — каждая игра сама решает что делать (START / PLAY AGAIN / etc.)
- `setGameHeader(title, hudHtml)` — игра вызывает в `init()` чтобы прописать заголовок в шапке + сгенерировать свои HUD-элементы по нужным `id`. Потом она же грабает рефы через `document.getElementById`.

Соответственно у каждой игры свой `init()`/`stop()`/`onOverlayClick()`, и она не знает про существование других игр.

## Pongonoid — правила

### Поле и объекты

| Параметр | Значение |
|---|---|
| Логические размеры canvas | 480 × 720 (px, рисуется в логических координатах, scale через `setTransform`) |
| Канвас рендерится с DPR | `window.devicePixelRatio` для чёткости на ретине / scaled-up десктопе |
| Ракетка | 90 × 8 px, отступ от края 18 px |
| Шарик | радиус 6 px |
| Блок | 40 × 18 px |
| Зазор между блоками | 3 px (одинаковый и в рядах, и между сторонами по центру) |
| Колонок в ряду | 12 |

### Управление

- Мышь / палец двигают ракетку по горизонтали
- Клик / тап запускает прилипший к ракетке шарик
- Шарик игрока стартует прилипшим, шарик ИИ запускается автоматически через ~800 мс

### ИИ

- Скорость 3.6 px/кадр (медленнее шарика)
- Целится с ошибкой: при каждом отскоке выбирает рандомный offset от центра ракетки в диапазоне ±45% её ширины
- Между отскоками offset чуть «дрожит», добавляя живости
- Не отслеживает шарики, летящие к игроку — только к себе

### Поле блоков

- В начале — 4 ряда по 12 блоков (2 над серединой, 2 под)
- Каждые **14 секунд** в центре появляются 2 новых ряда; существующие блоки сдвигаются от центра наружу
- Блоки, подошедшие слишком близко к ракетке (< 30px), удаляются
- Блоки выше середины поля рисуются чёрной заливкой (стиль ИИ), ниже — обводкой (стиль игрока). Стиль определяется текущей позицией, поэтому при сдвиге блок меняет вид

### Шарики

- **Скорость**: 5.6 px/кадр
- Каждый шарик помнит:
  - `owner` — кто его изначально запустил (`'player'` | `'cpu'`)
  - `lastHitBy` — кто последним отбил его ракеткой (для системы очков)
  - `disposable: bool` — основные шарики (`false`) возрождаются при вылете, клоны (`true`) — исчезают
- На поле всегда **2 основных шарика** (по одному у каждой стороны), плюс возможные клоны от splitter-блоков (cap `MAX_BALLS = 8`)
- Основные шарики возрождаются строго у своего владельца (`ball.owner`); ownership никогда не переключается

### Очки

| Событие | Очки |
|---|---|
| Блок твоим шариком (`lastHitBy == owner`) | +10 тебе |
| Блок «украденным» шариком (`lastHitBy != owner`) | +10 ударившему, +20 владельцу (×2) |
| Шарик прошёл за ракетку соперника | +100 тому, чей был последний удар |
| Шарик улетел за свою ракетку, последний удар твой | −50 (автогол) |
| Удар по армор-блоку | очки не начисляются (только сбивает броню) |

**Важно:** всплывающие цифры на поле показываются только для очков игрока. Очки бота меняются только в верхней панели HUD.

### Power-up блоки (специальные)

После того как **любая** сторона набирает **200 очков** (`SPECIAL_THRESHOLD`), каждые **7 секунд** (`SPECIAL_INTERVAL`) случайный живой обычный блок промоутится в один из 5 типов:

| Иконка | Тип | Эффект | Длительность |
|---|---|---|---|
| `○ ○` | **splitter** | Удваивает шарик: спавнит одноразовый клон с зеркальным `vx` | мгновенный |
| `◄—►` | **extend** | Твоя ракетка +2 секции (с 90 → 135 px, cap `PADDLE_MAX`) | 8 сек |
| `►—◄` | **shrink** | Соперника −2 секции (с 90 → 45 px, floor `PADDLE_MIN`) | 8 сек |
| `║║║` | **shield** | Линия твоих ворот непробиваема: шарики отскакивают от края | 6 сек |
| `▭▭` | **armor** | Твои живые блоки требуют **2 удара** для слома; новые блоки в твоём ряду тоже armored, пока эффект активен | 8 сек |

Промоушн (`promoteSpecial()`) выбирает только `type === 'normal' && armor === 0` блоки.

### Защита от каскада

`for (const ball of state.balls)` в JS итерирует по новым элементам, добавленным во время цикла, что позволяет одному удару по splitter-блоку запустить лавину клонов в одном кадре. Защита: **снапшот** массива в начале update-loop:

```js
const ballsThisFrame = state.balls.slice();
for (const ball of ballsThisFrame) { ... state.balls.push(clone) }
```

Клон обработается только в следующем кадре.

### Возрождение шарика

```js
function respawnBall(ball) {
  const fresh = makeBall(ball.owner);
  Object.assign(ball, fresh);
}
```

Просто пересоздаём шарик у изначального владельца. Никакой логики «отдать тому, у кого пусто» — она раньше была, но из-за неё основной шарик игрока мог перевыпуститься как CPU-шарик. Теперь жёстко: 2 основных, по одному на сторону, всегда.

Disposable клоны не идут через `respawnBall` — они проходят через `retireBall(ball)`:
```js
function retireBall(ball) {
  if (ball.disposable) { ball.removed = true; return; }
  respawnBall(ball);
}
```

Затем в конце кадра `state.balls = state.balls.filter(b => !b.removed)`.

### Стили шариков

| Шарик | Style | Color |
|---|---|---|
| Игрок, основной | обводка | `state.playerColor` |
| ИИ, основной | заливка | `state.playerColor` |
| Игрок, клон | обводка | `#000` |
| ИИ, клон | заливка | `#000` |

Сейчас **режим бесконечный**. Игра не заканчивается по очкам, выход — кнопка BACK в шапке. Можно добавить порог («первый до 500») — пока не реализовано.

## Space Slicer — правила

### Главная идея

Space Invaders, в котором снаряд игрока **разрезает** вражеский корабль вертикальной линией ровно по своей x-координате. Половинки становятся физическими телами с гравитацией и вращением, **рассыпаясь на пиксели** в процессе падения. Половинки/пиксели наносят урон игроку и укрытиям. Враг **не умирает с одного попадания** — выживает, пока в большей половине осталось ≥50% оригинальных клеток.

### Поле и объекты

| Параметр | Значение |
|---|---|
| Логические размеры canvas | 480 × 720 |
| Сетка врагов | 4 ряда × 6 колонок = 24 |
| Размер спрайта врага | 15×11 клеток × 3 px = 45×33 px |
| Размер игрока | 38×22 px |
| Укрытий | 3 |
| Сетка укрытия | 18×11 клеток × 4 px = 72×44 px |
| Жизни | 3 |
| Лимит снарядов в полёте | 3 |
| Скорость снаряда | 13 px/кадр |

### Управление

- **Десктоп**: `← →` / `A D` / мышь — двигать корабль. `Space` / `W` / `↑` / клик — выстрел.
- **Мобильный**: drag пальцем по экрану двигает корабль. Тап — выстрел.

### Враги (4 силуэта, пиксельный битмап)

Битмапы определены ASCII-строками 15 столбцов × 11 строк, парсятся через `parseBitmap()`. 4 паттерна:
- `0` Crab — широкий корпус, 2 антеннки, 4 ноги
- `1` Squid — узкая голова с пиком, 6 щупалец
- `2` Octopus — широкий низкий корпус, много ножек
- `3` Drone — угловатый дротик (резервный, в текущей раскладке не используется)

Раскладка по рядам: `[1, 0, 0, 2]` (squid · crab · crab · octopus сверху вниз).

Каждый враг — объект `{ cells, bw, bh, cs, cx, cy, alive, totalCells }`. `totalCells` — изначальное кол-во заполненных клеток, нужно для проверки порога смерти.

### Слайс-механика

При попадании снаряда (его x пересекает живую колонку битмапа):
1. Битмап делится на левую (`c < sliceCol`) и правую (`c ≥ sliceCol`) половины через `sliceBitmap()`
2. Считается `leftCount` и `rightCount` живых клеток
3. **Бóльшая половина**: если `bigCount >= e.totalCells * 0.5` → остаётся врагом (`e.cells = keepCells`), враг живой. **+2 очка**.
4. **Меньшая половина**: становится `fragment` через `makeFragment(cells, sourceEnemy, hSign)` где `hSign` = +1 (улетает вправо) или -1 (влево).
5. **Если bigCount < 50%**: враг умирает (`e.alive = false`), **обе половины** становятся фрагментами. **+12 очков**.
6. Снаряд гасится после первого слайса (`shot.removed = true`), не «прошивает» ряд.

### Fragment → Particles decay

Каждый осколок:
- Хранит `cells` (битмап своей половины), `aliveCells` (массив [r,c] живых клеток для O(1)-сэмплинга), `localCx/Cy` (смещение от центра спрайта к центру масс — точка вращения), `angle`, `omega`, `vx`, `vy`, `age`.
- Первые 9 кадров (`f.age <= 9`) падает целиком — видно силуэт половины.
- С 10-го кадра каждый кадр отрывает `shedN = ceil(aliveCells.length * 0.07)` клеток.
- Каждая оторванная клетка имеет 30% шанс (`PARTICLE_SPAWN_CHANCE`) стать летящей `particle`. Остальные просто тихо исчезают (визуально-же клетка пропадает из спрайта).
- Когда `aliveCells.length === 0`, осколок помечается `removed = true`.

`particles[]` — отдельный массив, каждая частица: `{ x, y, vx, vy, size, removed }`. Физика — гравитация + трение, без вращения. **Каждая частица опасна** для игрока (1 жизнь + invuln) и для укрытий (выгрызает ~1 клетку радиусом 3 px). Это и есть «угроза падающих кусков».

### Укрытия

3 «бункера» сетка 18×11 клеток (`cov.cells[r][c] : boolean`), клетка 4 px. Полный размер 72×44 px. Y-позиция: `PLAYER_Y - 92`. Расположены центрированно с 60px зазором.

Хит-радиусы:
- Снаряд игрока: 6 px (~3 клетки диаметром)
- Снаряд врага: 6 px
- Осколок (`fragment` контактирует центроидом): 10 px
- Частица: 3 px (~1 клетка)

Снаряд гасится при контакте с укрытием (sweep-check через `sweepShotIntoCover`). Осколок и частица — тоже гасятся.

### Враги стреляют

Каждый кадр с вероятностью `ENEMY_SHOT_PROB_BASE * state.wave` (0.006 на волне 1, 0.018 на волне 3) случайный живой враг стреляет вниз. Скорость `4.2 px/кадр`. Внешне — две короткие чёрточки («лазер»). Попадание в игрока — урон + invuln 90 кадров. Попадание в укрытие — выгрызает дыру.

### Волны

После очистки всех врагов + полного рассеивания осколков:
- `state.wave++`
- Спавнится новая партия (`buildEnemies()`)
- Показывается крупная надпись `WAVE N` на 1.5 секунды
- Марш формации ускоряется (`waveFactor = max(0.55, 1 - (wave-1)*0.08)`)
- Частота стрельбы врагов растёт линейно с волной

Игра бесконечная — конец только по `lives <= 0` или когда враг достиг линии `ENEMY_DANGER_Y = PLAYER_Y - 28`.

### Очки

| Событие | Очки |
|---|---|
| Слайс без убийства (бóльшая ≥50%) | +2 |
| Слайс с убийством (бóльшая <50%) | +12 |

### Звуки

Все Web Audio, без файлов:
- `sfxShoot` — square sweep 900→220 Hz
- `sfxSlice` — sawtooth sweep 1800→400 Hz + noise burst
- `sfxThud` — sine sweep 180→60 Hz (удар по укрытию / гашение осколка)
- `sfxHurt` — sawtooth sweep 220→70 Hz
- `sfxEnemyShoot` — sawtooth sweep 280→140 Hz
- `sfxGameOver` — 3 нисходящие триангулы
- `sfxWin` — C5-E5-G5-C6 (мажорный арпеджио, не используется в бесконечном режиме но определён)

### Ключевые имена / функции в модуле SpaceSlicer

- `BITMAPS` — массив 4 битмапов (boolean[][][])
- `parseBitmap(rows)` — парсит ASCII-строки в 2D-массив booleans
- `enemyAABB(e)` — tight AABB по живым клеткам (важно для повреждённых врагов в марше)
- `sliceBitmap(cells, bw, bh, sliceCol)` — возвращает [leftCells, rightCells]
- `shotHitsEnemyColumn(shotX, e)` — возвращает col или -1

## Звуки в Pongonoid

Все звуки генерируются через Web Audio API на лету, без mp3-файлов. Базовая функция `playDrop(freq, gain, dur, pitchUp)` создаёт «капельный» звук — короткий синусный тон с быстрым понижением высоты от ×pitchUp до базы, плюс высокая обертонная гармоника для шиммера.

| Событие | Параметры |
|---|---|
| Удар по блоку | `freq` зависит от Y, `gain 0.16`, `dur 0.18s` |
| Удар ракетки | глубже, `gain 0.20`, `dur 0.22s` |
| Стена | короче и тише, `gain 0.10`, `dur 0.12s` |
| Гол | двойной восходящий звон 1100→1500 Гц |
| Автогол / штраф | низкий тон 220 Гц |
| Сплит шарика | яркий высокий чайм `pitchForY(y) * 1.5` |
| Армор-чип | глуше: `pitchForY(y) * 0.7`, `pitchUp 0.9` |
| Extend | выше: `pitchForY(y) * 1.3` |
| Shrink | ниже: `pitchForY(y) * 0.8` |

`pitchForY(y)` возвращает 520 Hz внизу → 880 Hz вверху. Плюс `rand(0.97, 1.04)` чтобы серия ударов не звучала идентично.

Аудио активируется при первом нажатии START (требование браузеров — без user gesture звук заглушен).

- `touch-action: none` и `overscroll-behavior: none` на body, чтобы не дёргался экран при свайпе
- `position: fixed` на body для блокировки скролла страницы
- Канвас рендерится с `devicePixelRatio` для чёткости на retina/scaled-up десктопе. CSS-размер сохраняет пропорцию 480:720, физический размер — `cssSize × dpr`. Преобразование делается через `ctx.setTransform(scale * dpr, 0, 0, scale * dpr, 0, 0)`.
- **Touch-зона на мобилке**: листенеры висят на `canvas-wrap` (родитель канваса), а не на самом канвасе. На телефонах канвас letter-/pillar-боксится, в пустом нижнем пространстве (~100-120px на типичном iPhone) палец управляет ракеткой не закрывая её.
- ⚠️ Touch-обработчики на `canvas-wrap` гейтятся условием `if (!running) return` — иначе `e.preventDefault()` от `onMove` блокирует синтезированный `click` на START-кнопке оверлея, и она не срабатывает на мобилке.
- На узких экранах (≤600px) корнер-мета мельчает, `mmxxvi` и подпись делят футер аккуратно. Side-rules показываются только на ≥1100px.

## Журнал ключевых решений

1. **Чёрно-белая обводочная эстетика** — выбрано вместо неонового киберпанка
2. **Ряды появляются в центре** — раньше прибавлялись с краёв, давило на ракетку
3. **Зазор между блоками 3 px** — одинаковый везде; раньше изначальные ряды сливались по центру
4. **Скорость шарика 5.6** — повышали с 4.2
5. **Удар бота с разбросом ±45%** — раньше всегда возвращал шарик строго вертикально
6. **Интервал новых рядов 14 сек** — было 7, удвоили чтобы не давило
7. **Система очков вместо жизней** — начинали с 3 жизней, переделали на счёт. Игра бесконечная
8. **Очки за блок ×2 владельцу** — поощряет «крадёные» удары
9. **Попапы только у игрока** — раньше показывались для обоих, спамило
10. **Каждый шарик возрождается у своего владельца, ownership не меняется** — раньше пытались роутить «у кого пусто», но это могло перекинуть игрока без основного шарика
11. **Случайный цвет ракетки + основных шариков** — единый акцентный цвет на партию
12. **Звуки-капли** — Web Audio, без файлов, чтобы оставить один HTML-файл
13. **DPR-рендер** — десктоп выглядел шакально без него
14. **Power-up блоки** — splitter / extend / shrink / shield / armor; разнообразие после 200 очков
15. **Сплиттер генерит одноразовых клонов** — иначе клоны бесконечно плодятся через respawn
16. **Снапшот ball-list в update-loop** — иначе цепные сплиты в один кадр заполняли поле
17. **Armor self-blocks, не opponent** — пользователь буквально просил «у соперника», но это было бы дебаф на себя; интерпретировали как self-buff (мои блоки сложнее ломать сопернику)
18. **Touch-зона на canvas-wrap** — палец на мобилке не закрывает ракетку
19. **Touch-handler гейтится на `running`** — без этого preventDefault блокировал START на мобилке
20. **Главная — карточный хаб** — узкие горизонтальные карточки, под каждую игру свой `data-game="<id>"` и описание (`pong × arkanoid · vs ai` / `invaders · they fall in pieces`)
21. **Caveat был у подписи seksykotik, потом заменили на JetBrains Mono** — пользователь хотел чтоб подпись не выделялась шрифтом
22. **Abyssinica SIL без italic** — синтетический наклон выглядит криво

### Решения по Space Slicer

23. **Pixel-grid представление врагов, не полигоны** — пробовали полигональные силуэты, выглядели «так себе». Пиксельные ASCII-битмапы 15×11 даёт чёткий чанковый Space-Invaders look и тривиальный слайс (split по колонке)
24. **HP-механика «50% оставшейся массы»** — без неё клипом одного пикселя враг умирал. Теперь нужно срезать значительную часть, что добавляет тактики (выгрызать с края → больше осколков на голову игроку vs резать в центр → +12 очков сразу)
25. **Снаряд гасится после первого слайса** — раньше прошивал всю колонку, что было слишком ОП
26. **Fragment → particles decay** — половинки рассыпаются на отдельные пиксели в полёте, начиная с 10-го кадра. Создаёт ощущение «органического разрушения», а не «телепортации». Частицы наследуют скорость + малый рандомный разлёт
27. **PARTICLE_SPAWN_CHANCE = 0.30** — изначально 100% (каждая клетка становилась частицей), но было слишком много. Сейчас 30% становятся видимыми/опасными, остальные тихо исчезают
28. **Частицы наносят урон** — иначе осколки распадались в воздухе, и реально к игроку прилетали только безопасные «спецэффекты». Каждая частица: -1 жизнь у игрока (с invuln-гейтом) и ~1 клетку у укрытия
29. **`enemyAABB` считает по живым клеткам, не по полному битмапу** — повреждённые враги (с одним выбитым боком) корректно ведут себя в марше и в danger-line check
30. **Архитектура мультиигровая** — `Games[id]`, `setGameHeader()`, общий overlayBtn-диспетчер. Каждая игра — изолированный IIFE, не знает про другие
31. **Pinball-808 заархивирован** — концепция была интересная (пинбол как 808-драм-машина с квантованием), но геймплейно не зашло. Снимок в `archive/pinball-808.html`, играется как есть

### Шаги для добавления игры №3

Архитектура уже мультиигровая (см. секцию «Мультиигровая инфраструктура» в начале), так что:

1. **Скопировать паттерн** одного из существующих модулей (Pongonoid или SpaceSlicer) как стартовую точку.
2. **Добавить карточку в хаб**: один `<button class="game-card" data-game="<id>">` рядом с двумя существующими; ID должен совпасть с ключом, под которым модуль зарегистрируется в `Games`.
3. **Внутри модуля**:
   - Грабнуть рефы на `canvas`, `ctx`, `overlay`, `overlayTitle`, `overlayText` (НЕ хранить ref на `overlayBtn` — общий, диспетчер сам зовёт `onOverlayClick`)
   - В `init()` вызвать `setGameHeader(title, hudHtml)` с нужными `id` для HUD-элементов, потом грабнуть рефы через `getElementById`
   - В конце IIFE: `Games.<id> = { init, stop, onOverlayClick }; return Games.<id>;`
4. **Input-листенеры**: гейтить либо на `if (currentGame !== <ModuleName>) return`, либо на собственном флаге `running`. Touch-обработчики на `canvas-wrap` (родитель), а не на самом canvas — палец не закрывает игровое поле на мобилке.
5. **Обновить бейдж**: в `.title-stamp` сменить число editions, если игр стало больше.

### Общая инфраструктура (доступна всем играм)

- `canvas`, `ctx` — общий canvas-элемент, переинициализируется каждой игрой через свой `resizeCanvas()`
- `overlay`, `overlayTitle`, `overlayText`, `overlayBtn` — общий оверлей. Игры зовут `showOverlay()` локально, текст пишут в `overlayTitle/overlayText`. `overlayBtn` click диспетчерится из хаба.
- `currentGame` — глобальная переменная (let на верхнем уровне script), на ней основан тач/keyboard-гейтинг
- `setGameHeader(title, hudHtml)` — пишет в `#gameTitle` и `#gameHud`
- `BACK` button — общий, зовёт `currentGame.stop()` и убирает game-screen

### Игра должна определить локально

- `state`, `reset()`, `step()`, `draw()`, `loop()`, `start()`, `stop()`, `init()`, `onOverlayClick()`
- Свой `resizeCanvas()` (логические W/H её игры)
- Свои `showOverlay/hideOverlay` (Pongonoid и Slicer имеют свои локальные версии — overlay-элементы общие, но управление инкапсулировано)
- Свой звук (Web Audio контекст можно создавать per-game; в Slicer и Pongonoid сделано так)
- Свои input-листенеры (с правильным гейтингом)

### Что разумно учесть для третьей игры

## Конвенции в коде

- Все размеры/константы — в начале модуля, UPPERCASE
- Логические координаты 480×720, canvas масштабируется через `setTransform`
- Координаты `+0.5` при `strokeRect` — для пиксель-перфектных линий
- Цвета: `#000` ink, `#fff` bg, плюс `PLAYER_COLORS`
- Никаких внешних библиотек — всё ваниль
- Один файл `index.html` (без раздробления на модули)
- При правках уточнять, какую часть меняем (хаб / Pongonoid / стили / звуки / декорации / hub-nav)
- После каждой правки — `node --check` на извлечённом скрипте:
  ```bash
  sed -n '/<script>/,/<\/script>/p' index.html | sed '1d;$d' > /tmp/g.js && node --check /tmp/g.js
  ```

### Полезные глобалы и хелперы (в Pongonoid модуле)

- `state.gameTime` — миллисекунды от старта партии
- `state.playerColor` — выбранный акцентный цвет на партию
- `awardPoints(side, points, x, y)` — добавляет очки и попап (попап только если side === 'player')
- `addPopup(x, y, points, side)` — плавающий +N
- `state.popups` — массив, каждый с `life` 0..1, фейдится за ~0.9s
- `playDrop(...)` — все звуки идут через него, остальные функции `soundBlock/Paddle/Wall/Score/Penalty` — обёртки
- `pickPlayerColor()` — рандом из палитры
- `sideOfBlock(b)` — `'cpu'` если блок выше midY, иначе `'player'`
